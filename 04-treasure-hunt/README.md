# Project B: Treasure Hunt

## 1. Summary

An exhibition-wide game. During a session (for example 10:00 to 12:00), visitors scan as many different stall logos as possible with the QuickLook app. Each new stall adds points. The top visitors when the session ends win the session's prizes.

**QuickLook sends us every scan** (decision D-20). Their backend calls our API for each stall logo scan, encrypted. We keep every scan with the time we received it, count each event logo once per visitor per session, rank the visitors and work out the winners at the end of each session.

## 2. Visitor journey

1. Sign in to the QuickLook app and scan stall logos during the session.
2. QuickLook's backend sends each scan to our API straight away (logo ID, user ID, user name).
3. We store the scan. The first scan of an event logo by a visitor in the session adds 10 points, repeats do not.
4. The leaderboard screen and the hunt page on phones show the top players by player number.
5. When the session ends the standings are frozen, the provisional winners are listed and flagged in the database, and staff confirm them in the LKDR Admin Dashboard.
6. Winners collect their prize at the LKDR stall. Staff find the winner's phone number in QuickLook with their user ID.

## 3. Event logos

The event logos are the same for every session of the 3 days. Staff load them once from QuickLook on the first day (**Event logos**, then **Load logos from QuickLook**). Loading again adds logos QuickLook added later. A scan of a logo that is not in the list is stored but does not count.

## 4. Ranking

Most different event logos first. A tie goes to whoever reached that count first. Points are 10 per logo (a session setting). Winners of earlier sessions can win again unless the session setting says otherwise.

## 5. Identity

- Visitors do not sign in to the hunt. Our user ID is QuickLook's user ID, the same ID as in the game links.
- The public leaderboard shows a **player number** (for example "Player #27") and points, never names or user IDs.
- Staff see the user name and QuickLook user ID, and every scan received for a player.

## 6. Connection per environment

| Setting | Where |
|---|---|
| Scan key (QuickLook encrypts with it) | SSM `/lkdr/{stage}/hunt/scan-key` (SecureString). Generated by the deploy script, kept in `.state/secrets.env` as `HUNT_SCAN_KEY`. Share it with QuickLook outside email |
| Logo list API address | SSM `/lkdr/{stage}/hunt/leaderboard-base-url` (String), to be confirmed by QuickLook |
| Logo list API key | SSM `/lkdr/{stage}/hunt/leaderboard-api-key` (SecureString), backend only |

The scan format QuickLook builds against is part E of the [integration contract](../06-quicklook-integration/integration-contract.md#e-treasure-hunt-scans-quicklook-backend-to-our-api-decision-d-20).
